# 自动配置原理剖析

## 一、核心知识讲解

### 1.1 Spring Boot自动配置概述

*   **定义**：Spring Boot的自动配置是指它能够根据项目中添加的依赖和配置文件，自动设置好相关的Bean，从而简化了开发者的工作。
*   **作用**：通过自动配置，可以减少大量的XML配置或者Java配置代码，使得项目更加简洁易维护。

### 1.2 条件注解

*   **@ConditionalOnClass**：当类路径下存在指定类时，才进行配置。
*   **@ConditionalOnMissingBean**：当容器中不存在指定类型的Bean时，才会创建新的Bean。
*   **@ConditionalOnProperty**：当指定属性有值且为true时，才会触发配置。

### 1.3 配置文件解析

*   **application.properties/yml**：Spring Boot会自动读取这些配置文件中的内容，并将其应用到对应的Bean上。
*   **默认配置**：Spring Boot提供了很多默认配置，只有在没有自定义配置的情况下才会生效。

## 二、详细示例 / 案例分析

### 2.1 自动配置案例

假设我们有一个简单的Web应用，需要集成Thymeleaf模板引擎。只需在`pom.xml`中添加Thymeleaf依赖，Spring Boot就会自动为我们配置好Thymeleaf的相关Bean。

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-thymeleaf</artifactId>
</dependency>
```

### 2.2 自定义自动配置

如果需要对某些自动配置进行定制，可以通过实现`ApplicationRunner`或`CommandLineRunner`接口，在应用启动后执行自定义逻辑。

```java
@Component
public class MyCustomConfig implements ApplicationRunner {
    @Override
    public void run(ApplicationArguments args) throws Exception {
        System.out.println("Custom configuration is running...");
    }
}
```

## 三、实践练习

*   **题目1**：尝试在你的Spring Boot项目中添加一个新的starter依赖（如Spring Data JPA），并观察Spring Boot是如何自动配置相关Bean的。
*提示*：检查`application.properties`文件以及日志输出，了解哪些Bean被自动配置了。
*   **题目2**：编写一个自定义的自动配置类，要求当某个特定条件满足时（例如存在某个特定的类），该配置类生效并打印一条消息。
*提示*：使用`@ConditionalOnClass`注解来控制配置类是否生效。
