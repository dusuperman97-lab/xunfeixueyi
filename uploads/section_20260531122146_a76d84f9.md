# 配置文件与多环境管理

## 一、核心知识讲解

### 1.1 配置文件概述

*   **配置文件作用**：Spring Boot 应用程序的配置文件主要用于定义应用程序的各种属性，如数据库连接信息、日志级别等。
*   **常用配置文件**：`application.properties` 或 `application.yml`，它们位于 `src/main/resources` 目录下。

### 1.2 多环境支持

*   **多环境需求**：在开发、测试和生产环境中，配置参数可能不同。Spring Boot 提供了多种方式来管理这些不同的环境配置。
*   **profile机制**：通过在配置文件中使用特定的 profile（如 `application-dev.properties`），可以为不同的环境设置不同的配置。
*   **激活profile**：可以通过命令行参数（如 `--spring.profiles.active=dev`）或在 `application.properties` 中指定激活的 profile。

### 1.3 配置文件优先级

*   **优先级顺序**：Spring Boot 会按照一定的优先级顺序加载配置文件，通常情况下，`application.properties` 的优先级低于特定 profile 的配置文件。
*   **覆盖规则**：后加载的配置文件中的属性会覆盖先加载的相同属性。

## 二、详细示例 / 案例分析

### 2.1 创建多环境配置文件

假设我们有一个 Spring Boot 应用程序，需要在开发、测试和生产环境中分别使用不同的数据库连接信息。

1. 在 `src/main/resources` 目录下创建以下配置文件：
   - `application-dev.properties`
   - `application-test.properties`
   - `application-prod.properties`

2. 在每个配置文件中设置相应的数据库连接信息：

```properties
# application-dev.properties
spring.datasource.url=jdbc:mysql://localhost:3306/dev_db
spring.datasource.username=root
spring.datasource.password=root
```

```properties
# application-test.properties
spring.datasource.url=jdbc:mysql://test-server:3306/test_db
spring.datasource.username=test
spring.datasource.password=test
```

```properties
# application-prod.properties
spring.datasource.url=jdbc:mysql://prod-server:3306/prod_db
spring.datasource.username=prod
spring.datasource.password=prod
```

### 2.2 激活profile

1. 通过命令行参数激活profile：
   ```sh
   java -jar myapp.jar --spring.profiles.active=dev
   ```

2. 在 `application.properties` 中指定激活的profile：
   ```properties
   spring.profiles.active=dev
   ```


## 三、实践练习

*   **题目1**：创建一个 Spring Boot 项目，并为其添加三个不同的环境配置文件（开发、测试、生产）。确保每个环境的数据库连接信息不同。
*提示*：可以在 `application.properties` 文件中设置默认的数据库连接信息，然后在各自的环境配置文件中覆盖这些默认值。
*   **题目2**：编写一个简单的服务类，该服务类能够读取并打印当前激活的profile名称。
*提示*：可以使用 `@Value("${spring.profiles.active}")` 注解来注入当前激活的profile名称。
