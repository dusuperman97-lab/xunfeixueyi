# RAG 与 GraphRAG 的本质区别

## 一、核心知识讲解（25%）
### 1.1 RAG：检索增强生成的基本范式
*   **检索增强生成（RAG）**：是一种将外部知识库检索能力与大语言模型（LLM）生成能力深度融合的架构范式。其核心思想是——在模型生成回答前，先从结构化或非结构化文档库中检索出与用户问题最相关的若干片段（chunks），再将这些片段连同原始问题一同输入LLM，引导模型基于事实依据生成准确、可溯源的回答。RAG并非替代LLM，而是为其提供‘外挂记忆’和‘实时知识更新通道’，有效缓解大模型固有的幻觉（hallucination）、知识陈旧和缺乏可解释性三大痛点。典型流程包含三阶段：查询理解与向量化→稠密向量相似度检索→上下文注入与条件生成。例如，当提问‘2025年Q1中国新能源汽车销量前三品牌’时，RAG系统会先检索最新行业报告PDF中的销量表格段落，再让LLM仅基于该表格数据作答，而非依赖其训练截止日期前的参数化记忆。

### 1.2 GraphRAG：以知识图谱为中枢的增强范式
*   **GraphRAG**：是在RAG基础上的重大演进，其本质区别在于将扁平化的文本片段检索升级为**基于知识图谱（Knowledge Graph）的结构化语义检索与推理**。它不再简单返回孤立的文本块，而是构建一个由实体（如‘比亚迪’‘特斯拉’‘销量’‘2025年Q1’）和关系（‘隶属’‘销量排名’‘时间归属’）构成的多跳互联网络。当用户提问时，GraphRAG首先在图谱中定位相关实体节点，然后沿关系边进行多跳遍历（如从‘比亚迪’→‘销量’→‘2025年Q1’→‘数值’），聚合路径上的结构化属性与上下文，最终驱动LLM生成具备逻辑链条、因果推断和跨文档关联能力的回答。这使得GraphRAG能回答‘为什么比亚迪在Q1销量超越特斯拉？是否与其电池技术专利布局相关？’这类需要隐含关系挖掘与归因分析的复杂问题，而传统RAG仅能罗列各自销量数字。

## 二、详细示例与案例（25%）
### 2.1 应用场景：医疗问诊辅助系统的决策差异
在构建AI医生助手时，面对患者主诉‘持续低烧伴夜间盗汗三个月，近期体重下降5kg’，RAG系统会检索医学指南中关于‘结核病症状’的段落，返回‘低热、盗汗、消瘦为典型三联征’等描述，并生成‘需考虑结核感染可能’的结论。但该结论缺乏个体化推理：未关联患者是否曾赴结核高发区旅行、是否接触过确诊者、是否有HIV感染史等关键风险因子。而GraphRAG则将患者电子病历、检验报告（如CD4计数、PPD试验结果）、流行病学数据库构建成动态图谱，自动触发‘低烧+盗汗+消瘦’→‘激活结核风险子图’→‘匹配旅行史节点’→‘关联CD4<200节点’→‘强化HIV合并结核诊断假设’的推理链，输出‘高度怀疑HIV相关结核病，建议立即启动痰涂片+GeneXpert检测及CD4复查’，显著提升临床决策的精准性与可追溯性。

from langchain.llms import OpenAI

## 四、常见误区（10%）
### 4.1 易错点：将GraphRAG简单理解为‘RAG+知识图谱可视化’
错误表现是仅在RAG前端增加图谱关系图展示，后端仍使用传统向量检索。根本原因在于混淆了‘图谱作为存储介质’与‘图谱作为推理引擎’的本质差异——前者仅提供静态关系视图，后者要求查询时动态执行多跳路径计算与子图聚合。正确做法是重构检索层：用图数据库（Neo4j/Amazon Neptune）替代向量库，设计Cypher/SPARQL查询替代相似度排序，并将图谱路径结果结构化注入LLM提示词。避免方法包括：严格验证检索结果是否包含≥2跳关系路径（如A→B→C而非仅A→B），以及在评估指标中加入‘关系覆盖率’（检索结果中实体间显式关系占比）而非仅‘文本召回率’。

## 六、小结与思考（10%）
### 6.1 核心要点回顾
RAG与GraphRAG的本质区别不在技术堆叠，而在**认知范式跃迁**：RAG解决‘知道什么’（what），GraphRAG解决‘为何如此’（why）与‘如何关联’（how）。前者依赖文本表面相似度，后者依赖语义深层结构；前者输出事实罗列，后者输出推理链条；前者适配静态知识问答，后者赋能动态决策支持。掌握这一区别，是构建下一代企业级AI应用的认知基石。

如果某医疗AI系统需判断‘患者服用华法林期间出现鼻出血，是否应立即停药？’，传统RAG可能检索到‘华法林禁忌症’文档，而GraphRAG会构建‘患者INR值-药物剂量-出血部位-凝血酶原时间’动态子图。请思考：在此场景中，图谱哪些关系边最为关键？缺失哪类实体会导致推理失效？
