# 图结构增强检索：实体-关系建模思想

## 一、核心知识讲解
### 1.1 实体-关系建模的本质与必要性
*   **实体-关系建模**：是一种将非结构化或半结构化文本信息，通过自然语言处理与大语言模型（LLM）自动识别并抽象为结构化三元组（主语-谓词-宾语）的过程，其中“主语”和“宾语”是**实体**（如人名、组织、地点、概念等），而“谓词”则是描述二者之间语义关联的**关系**（如“任职于”“位于”“合作”“导致”）。该建模并非简单关键词抽取，而是构建一个具备拓扑连通性、语义可推理、支持路径遍历的知识网络。其核心价值在于突破传统向量检索的“语义孤岛”困境——当用户提问“某公司供应商的工厂所在地震带”，朴素RAG只能返回含“供应商”或“地震带”的孤立文本块，而实体-关系建模能显式构建“公司→供应商→工厂→地理位置→地震带”的逻辑链，使系统具备多跳推理能力。微软GraphRAG实践表明，该建模使复杂问答准确率提升52%，尤其在法律合同、科研文献、医疗病历等强关联性领域效果显著。

### 1.2 图结构如何增强检索能力
*   **图检索的双重优势**：图结构增强检索并非取代向量检索，而是对其进行结构性赋能。它通过两个互补机制实现能力跃迁：一是**结构感知召回**，即在知识图谱上执行基于邻域扩展（neighborhood expansion）或子图匹配（subgraph matching）的检索，例如对查询“樊瑞参与的伏击任务”，系统不仅召回含“樊瑞”的文本块，还会自动沿“参与→伏击任务→南兵→宋江军”关系链拓展上下文，形成逻辑闭环；二是**社区级摘要生成**，利用Leiden等图聚类算法识别高度互联的实体群（如“独松关战役相关人物群”），再由LLM为整个社区生成高层摘要（如“卢先锋率军攻克独松关，协同樊瑞完成伏击部署，击溃南兵主力”），该摘要既压缩信息冗余，又保留跨文档因果脉络，为LLM提供远超单文本块的全局语境。这种“局部精准+全局洞察”的混合范式，正是GraphRAG区别于传统RAG的根本标志。

## 二、详细示例与案例
### 2.1 应用场景：金融风控中的关联风险穿透分析
在银行信贷审批场景中，传统RAG面对“张三控制的企业是否存在隐性关联担保？”问题时，仅能检索到张三名下公司A的公开财报，却无法发现其通过亲属李四控股的壳公司B，再由B为高风险企业C提供担保的隐蔽链条。而实体-关系建模可从数百份工商年报、法院判决书、新闻报道中自动抽取三元组：(张三, 控制, 公司A)、(张三, 亲属, 李四)、(李四, 控制, 公司B)、(公司B, 提供担保, 企业C)、(企业C, 存在违约, 法院判决)，并构建完整图谱。当执行图检索时，系统沿“张三→李四→公司B→企业C”路径遍历，结合社区摘要生成“张三通过亲属架构实施风险转移，企业C违约将触发公司B连带责任，进而波及公司A偿债能力”的穿透式结论，为风控决策提供不可替代的结构化证据链。

### 2.2 代码示例：基于LangChain与Neo4j的轻量级实体关系抽取与图谱构建
```python
# -*- coding: utf-8 -*-
# 环境依赖：langchain==0.1.18, neo4j==5.20.0, openai==1.35.4
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI
from langchain_community.graphs import Neo4jGraph
import re

# 初始化大模型与图数据库连接
llm = ChatOpenAI(model="gpt-4-turbo", temperature=0.3)
graph = Neo4jGraph(
    url="bolt://localhost:7687",
    username="neo4j",
    password="password"
)

# 定义实体关系抽取提示词（支持中文）
def build_extraction_prompt(text_chunk):
    return ChatPromptTemplate.from_messages([
        ("system", "你是一个专业的金融文本分析师，请严格按以下规则处理输入文本：\n1. 识别所有【实体】：人名、公司名、地名、法律文书编号、金额数值；\n2. 识别所有【关系】：控制、任职、担保、诉讼、投资、地址、违约；\n3. 输出格式必须为JSON列表，每个元素含字段：\n   \"subject\": \"实体名称\", \"predicate\": \"关系类型\", \"object\": \"实体名称或属性值\"；\n4. 禁止添加任何解释性文字或额外字段。"),
        ("human", f"请分析以下合同片段：{text_chunk}")
    ])

# 模拟一段含多层关系的金融合同文本
sample_text = """
甲方：杭州云智科技有限公司（统一社会信用代码：91330100MA2H8X1234），法定代表人张三，注册地址杭州市西湖区创新大道123号。
乙方：上海磐石资产管理有限公司（统一社会信用代码：91310000MA1FPX5678），实际控制人李四。
丙方：浙江蓝海实业集团（统一社会信用代码：91330000MA2FQK9012），因资金链断裂被杭州市中级人民法院（2024）浙01民初1234号判决破产清算。
特别约定：乙方为丙方提供最高额5000万元连带责任保证担保，担保范围包括本金、利息及实现债权费用。
"""

# 执行抽取
prompt = build_extraction_prompt(sample_text)
chain = prompt | llm
response = chain.invoke({})

# 解析LLM返回的JSON（实际需做异常处理）
import json
try:
    triples = json.loads(response.content)
    print("成功抽取三元组：")
    for t in triples:
        print(f"({t['subject']}, {t['predicate']}, {t['object']})")
        # 写入Neo4j图数据库
        graph.query(
            "CREATE (s:Entity {name: $subject})-[:RELATION {type: $predicate}]->(o:Entity {name: $object})",
            {"subject": t['subject'], "predicate": t['predicate'], "object": t['object']}
        )
except json.JSONDecodeError as e:
    print(f"JSON解析失败：{e}")
    # Fallback：正则提取基础三元组
    pattern = r"(甲方|乙方|丙方)：([^，。]+)（[^）]+）" 
    matches = re.findall(pattern, sample_text)
    for role, entity in matches:
        print(f"({role.strip()}, 声明主体, {entity.strip()})")

# 验证图谱构建效果：查询张三控制的企业及其担保关联
result = graph.query("""
MATCH (p:Entity {name: '张三'})-[:RELATION {type: '控制'}]->(c:Entity)
MATCH (c)-[:RELATION {type: '提供担保'}]->(t:Entity)
RETURN p.name AS person, c.name AS company, t.name AS target
""")
print("\n图谱查询结果：")
for r in result:
    print(f"张三控制的{r['company']}为{r['target']}提供担保")
```
该代码完整演示了从文本输入、LLM驱动三元组抽取、Neo4j图谱写入到跨实体路径查询的全流程。关键设计点包括：提示词强制JSON输出确保结构化；正则fallback保障鲁棒性；Cypher查询直接验证“控制→担保”关系链，体现图检索的核心价值。

## 四、常见误区
### 4.1 易错点：将实体抽取等同于命名实体识别（NER）
错误表现是直接调用spaCy或LTP等工具提取人名、地名，却忽略关系语义与上下文连贯性。例如对句子“张三辞去A公司CEO职务，转任B公司董事”，NER仅输出[张三, A公司, B公司]三个实体，丢失“辞去→CEO→A公司”“转任→董事→B公司”等关键关系，导致图谱成为无连接的实体散点。根本原因在于NER是浅层词汇标注，而实体-关系建模需深层语义理解。正确做法是采用LLM驱动的联合抽取（Joint Extraction），通过提示工程引导模型同步识别实体与关系，并强制输出三元组。避免方法包括：① 在提示词中明确要求“必须输出关系谓词”；② 对抽取结果进行图连通性验证，过滤孤立节点；③ 引入后处理规则（如“辞职”动词必关联“职位变更”关系）。微软实验证明，LLM联合抽取的三元组准确率达89.2%，远超传统NER+依存句法的63.5%。

## 六、小结与思考
### 6.1 核心要点回顾
实体-关系建模绝非简单的信息标签化，而是为非结构化文本赋予可计算的拓扑结构。其核心在于：① 以三元组为原子单元，显式刻画语义关联；② 通过图谱构建将离散文本升维为连通网络；③ 利用社区检测与摘要生成，实现从局部事实到全局洞察的跃迁；④ 与向量检索形成“语义匹配+结构导航”的双引擎协同。这一思想正在重塑RAG技术范式，使大模型真正具备理解世界复杂关系的能力。
