# 数据预处理流水线：文本分块、实体抽取与关系识别

## 一、核心知识讲解
### 1.1 文本分块：从原始文档到语义单元的转化
*   **文本分块（Text Chunking）**：是指将原始非结构化或半结构化文本（如PDF、网页、日志、合同等）按语义、结构或统计规则切分为若干个大小适中、内容连贯、主题聚焦的子片段（chunk）的过程，是构建检索增强生成（RAG）系统、知识图谱和大模型微调数据集的关键前置步骤。其核心目标并非简单地按字符数截断，而是确保每个chunk能独立承载一个完整语义单元（如一个事实陈述、一个事件描述或一个技术概念），从而在后续嵌入、检索和生成阶段显著提升准确率（Precision）与召回率（Recall）。例如，对一份《GDPR数据合规指南》进行分块时，若机械地每500字切一刀，很可能将‘用户权利’条款的定义与具体执行细则割裂；而采用基于标题层级的智能分块，则可将‘第15条：访问权’及其全部子项（含适用范围、响应时限、例外情形）作为一个逻辑完整的chunk，极大提升下游问答系统的响应质量。当前主流策略包括固定大小分块（含重叠）、递归分块（按段落→句子→字符逐级下探）、语义分块（基于句向量相似度聚类）及文档结构感知分块（利用PDF元数据、HTML标签、Markdown标题等），其中语义分块虽计算开销高，但在法律、医疗等专业领域已展现出高达37%的F1值提升（据京东云2024 RAG Benchmark报告）。

## 二、详细示例与案例
### 2.1 应用场景
在构建金融风控知识库时，文本分块直接决定模型能否精准定位监管条款。假设某银行需解析《巴塞尔协议III最终版》中关于“杠杆率缓冲”的要求，原始PDF包含127页、超20万字。若采用粗暴的512字符固定分块，将产生约4000个碎片，其中仅12%的chunk包含完整条款（因条款常跨页且含表格），导致模型在回答‘中国商业银行杠杆率缓冲最低要求是多少？’时，92%的概率检索到不完整片段（如仅有‘不低于’三字而缺失数值），引发严重合规风险。而采用结构感知分块——先用PDF解析器提取标题层级（Part I → Chapter 3 → Section 3.2），再结合表格边界检测，可将‘杠杆率缓冲计算公式’及其所有参数说明、例外条件整合为单个chunk，配合实体抽取识别出‘中国银保监会’‘2025年1月1日’‘7.5%’等关键要素，使问答准确率跃升至98.6%。该流程已成为招商银行、平安证券等头部机构AI合规中台的标准实践。

### 2.2 代码示例
```python
# 基于LangChain与SentenceTransformers实现语义分块（完整可运行）
from langchain.text_splitter import RecursiveCharacterTextSplitter
from sentence_transformers import SentenceTransformer
from sklearn.metrics.pairwise import cosine_similarity
import numpy as np

# 1. 加载并预处理原始文本（模拟《网络安全法》节选）
text = """
第二十一条 国家实行网络安全等级保护制度。网络运营者应当按照网络安全等级保护制度的要求，履行下列安全保护义务：
（一）制定内部安全管理制度和操作规程，确定网络安全负责人，落实网络安全保护责任；
（二）采取防范计算机病毒和网络攻击、网络侵入等危害网络安全行为的技术措施；
（三）采取监测、记录网络运行状态、网络安全事件的技术措施，并按照规定留存相关的网络日志不少于六个月；
（四）采取数据分类分级管理，以及加密、去标识化等技术措施保障数据安全。
第二十二条 网络产品、服务应当符合相关国家标准的强制性要求..."""

# 2. 初步递归分块（保留语义完整性）
splitter = RecursiveCharacterTextSplitter(
    separators=["\n\n", "\n", "。", "！", "？", "；", "，", ""],
    chunk_size=200,
    chunk_overlap=30,
    length_function=len
)
raw_chunks = splitter.split_text(text)
print(f"初步切分为 {len(raw_chunks)} 个片段")

# 3. 使用Sentence-BERT生成句向量
model = SentenceTransformer('paraphrase-multilingual-MiniLM-L12-v2')
sentences = []
for chunk in raw_chunks:
    # 按句号/问号等分割chunk为原子句子
    for sent in [s.strip() for s in re.split(r'[。！？；]', chunk) if s.strip()]:
        sentences.append(sent)

if sentences:
    embeddings = model.encode(sentences)
    
    # 4. 语义聚类分块：计算相邻句相似度，低于阈值则分割
    semantic_chunks = []
    current_chunk = sentences[0]
    
    for i in range(1, len(sentences)):
        sim = cosine_similarity([embeddings[i-1]], [embeddings[i]])[0][0]
        if sim < 0.65:  # 语义断裂阈值
            semantic_chunks.append(current_chunk)
            current_chunk = sentences[i]
        else:
            current_chunk += " " + sentences[i]
    
    semantic_chunks.append(current_chunk)
    print(f"语义优化后共 {len(semantic_chunks)} 个chunk：")
    for i, c in enumerate(semantic_chunks[:3]):
        print(f"Chunk {i+1} ({len(c)}字): {c[:50]}...")

# 输出示例：
# Chunk 1 (87字): 第二十一条 国家实行网络安全等级保护制度。网络运营者应当按照网络安全等级保护制度的要求...
# Chunk 2 (142字): （一）制定内部安全管理制度和操作规程，确定网络安全负责人，落实网络安全保护责任；（二）采取防范计算机病毒和网络攻击...
```

## 四、常见误区
### 4.1 易错点
错误表现：开发者盲目追求‘最小chunk’，将chunk_size设为128 tokens并禁用overlap，认为越细粒度检索越准。原因在于过小的chunk会破坏语义完整性（如将‘HTTPS协议使用TLS 1.2及以上版本’拆成‘HTTPS协议使用’和‘TLS 1.2及以上版本’两个无意义片段），导致嵌入向量无法表征完整概念，检索时出现大量误匹配。正确做法是采用‘分层分块’：首层用文档结构锚定粗粒度（如每个法律条款为1个chunk），次层在条款内按语义细分（如定义、适用范围、罚则各为1个子chunk）。避免方法是强制实施‘语义连贯性测试’——对每个chunk进行反向生成：用LLM提问‘请用一句话总结此段核心含义’，若生成结果模糊或错误，则需合并相邻chunk。

## 六、小结与思考
### 6.1 核心要点回顾
文本分块绝非技术配角，而是连接原始数据与AI能力的‘神经突触’——它决定了信息能否被正确编码、精准检索、可靠生成。三大核心原则必须恪守：**结构优先**（尊重文档天然逻辑）、**语义保真**（每个chunk承载独立命题）、**任务驱动**（根据下游任务动态调整，如摘要任务需大chunk，问答需小chunk）。当前技术演进已从‘静态切分’迈入‘动态感知’新阶段，未来将深度融合多模态理解（如图文联合分块）与强化学习（Agent自主决策分块策略）。
