# JDK安装与IDE配置（IntelliJ IDEA）

## 一、核心知识讲解
### 1.1 JDK与IDE的基本概念与协同机制
*   **JDK（Java Development Kit）**：是Java语言的官方开发工具包，不仅包含Java运行时环境（JRE），还提供编译器（javac）、调试器（jdb）、打包工具（jar）等全套开发组件。它本质上是一套标准化的API集合与工具链，使开发者能将.java源代码编译为跨平台的.class字节码，并通过JVM执行。JDK版本演进直接影响语言特性（如JDK 8引入Lambda表达式、JDK 17成为LTS长期支持版），因此选择匹配项目需求的JDK至关重要——例如Spring Boot 3.x强制要求JDK 17+，而旧企业系统可能仍依赖JDK 8。

*   **IntelliJ IDEA**：是由JetBrains开发的智能Java集成开发环境（IDE），其核心优势在于深度代码分析引擎（IntelliSense）、实时错误检测、重构支持及插件生态。它并非简单编辑器，而是通过“Project SDK”机制与JDK建立双向绑定：一方面读取JDK提供的类库（rt.jar等）实现自动补全与类型校验；另一方面调用javac编译器执行构建任务，并将JVM参数注入运行配置。这种耦合关系决定了IDE无法脱离JDK独立工作，且SDK配置错误将直接导致“Cannot resolve symbol”或“Unsupported class file major version”等致命编译错误。

### 1.2 JDK安装全流程详解（含多平台适配）
*   **下载与版本选型策略**：访问Oracle官网（https://www.oracle.com/java/technologies/downloads/）或OpenJDK社区（https://adoptium.net/）获取JDK。初学者应优先选择LTS版本（如JDK 17或JDK 21），避免使用短期支持版（如JDK 20）。Windows用户下载.exe安装包，macOS选择.pkg格式，Linux则下载.tar.gz并解压至/usr/lib/jvm/。需特别注意：JDK 17+已移除JavaFX和JAXB模块，若项目依赖这些功能需单独引入Maven坐标。

*   **环境变量配置原理与实操**：JDK安装后必须配置JAVA_HOME（指向JDK根目录，非bin子目录）和PATH（追加%JAVA_HOME%\bin）。此配置使系统命令行能识别javac、java等指令。验证方式为终端执行`java -version`与`javac -version`，输出版本号一致即成功。若出现“command not found”，说明PATH未生效，需重启终端或执行`source ~/.bashrc`（Linux/macOS）。

## 二、详细示例与案例
### 2.1 全场景IDE配置实战（Windows/macOS/Linux三端统一）
以创建一个支持JUnit 5的Maven项目为例：首先启动IntelliJ IDEA，选择“New Project”，在向导中勾选“Maven”，点击“Next”。关键步骤在于“Project SDK”下拉框——若未显示已安装JDK，点击右侧“New...→JDK”，浏览至JDK安装路径（如Windows：C:\Program Files\Java\jdk-17.0.1，macOS：/Library/Java/JavaVirtualMachines/jdk-17.0.1.jdk/Contents/Home）。完成创建后，进入File→Project Structure→Project，确认“Project SDK”与“Project language level”均设为17。此时IDE会自动下载Maven依赖并索引JDK源码，右键src→New→Java Class即可开始编码。

### 2.2 多JDK共存管理与动态切换代码示例
```java
// 示例：在IDEA中为不同模块配置独立JDK（模拟微服务架构）
// 模块A（订单服务）使用JDK 17
// 模块B（报表服务）使用JDK 21（需更高性能GC）
// 配置路径：File → Project Structure → Modules → 选择对应模块 → Dependencies → Module SDK

// 实际项目结构示意（pom.xml片段）
<modules>
  <module>order-service</module>
  <module>report-service</module>
</modules>

// order-service/pom.xml中指定Java版本约束
<properties>
  <maven.compiler.source>17</maven.compiler.source>
  <maven.compiler.target>17</maven.compiler.target>
</properties>

// report-service/pom.xml中升级为JDK 21
<properties>
  <maven.compiler.source>21</maven.compiler.source>
  <maven.compiler.target>21</maven.compiler.target>
</properties>

// 编译验证脚本（build.sh）
#!/bin/bash
# 分别编译两个模块，验证JDK隔离性
cd order-service && mvn clean compile -Dmaven.compiler.release=17
cd ../report-service && mvn clean compile -Dmaven.compiler.release=21
```

## 四、常见误区
### 4.1 混淆JDK与JRE导致编译失败
*   **错误表现**：新建项目后提示“Cannot find javac”，或运行时抛出“NoClassDefFoundError: javax/xml/bind/DatatypeConverter”。
*   **根本原因**：将JRE（仅含运行时库）误设为Project SDK，或JDK安装时未勾选“Public JRE”选项导致bin目录缺失。JRE不含编译器，故无法执行javac；而JAXB等模块自JDK 11起被移除，需显式添加依赖。
*   **正确做法**：始终在IDEA中选择完整JDK路径（含lib、bin、jre子目录），通过终端验证`javac -version`是否可执行。若使用JDK 11+，需在pom.xml中补充：
```xml
<dependency>
  <groupId>javax.xml.bind</groupId>
  <artifactId>jaxb-api</artifactId>
  <version>2.3.1</version>
</dependency>
```
*   **避免方法**：安装JDK时勾选“Add to PATH”，并在IDEA配置中启用“Use project JDK for build process”选项，确保构建与运行环境一致。

## 五、实践建议
### 5.1 练习任务：构建双JDK兼容的Hello World项目
*   **步骤**：① 安装JDK 17与JDK 21；② 创建空项目，添加两个Module（hello-jdk17、hello-jdk21）；③ 分别为Module配置对应SDK；④ 在每个Module中编写HelloWorld.java，使用各自版本特有语法（如JDK 21的`String.isEmpty()`增强）；⑤ 执行Maven clean compile验证编译通过。
*   **预期结果**：两个Module均能独立编译，且IDEA底部状态栏显示对应JDK版本。
*   **验证方法**：右键Module→Open Module Settings→Dependencies，确认SDK路径正确；在Terminal中执行`mvn -pl hello-jdk17 compile`与`mvn -pl hello-jdk21 compile`，观察日志中的“Java version”字段。

## 六、小结与思考
### 6.1 核心要点回顾
JDK是Java开发的基石，其版本选择直接影响项目兼容性与性能上限；IntelliJ IDEA通过SDK抽象层实现JDK的灵活绑定，支持全局与模块级双重配置；环境变量配置是系统级前提，而IDE内配置是开发级保障；现代IDE已大幅降低配置门槛，但理解底层机制仍是排查问题的关键。

### 6.2 思考题
如果团队中同时存在JDK 8与JDK 17的遗留项目，如何设计统一的CI/CD流水线，确保不同JDK版本的项目能共享同一套Git仓库与构建脚本？请从Maven Profiles、Docker多阶段构建、以及IDEA Workspace配置三个维度阐述可行性方案。
