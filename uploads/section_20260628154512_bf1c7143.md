# JDK安装与配置

## 一、核心知识讲解
### 1.1 什么是JDK及其核心组成
*   **JDK（Java Development Kit）**：是Java语言的软件开发工具包，专为Java程序员设计，不仅包含运行Java程序必需的**JRE（Java Runtime Environment）**，还额外提供了编译器（javac）、调试器（jdb）、文档生成工具（javadoc）等开发工具。JDK是Java生态的基石，没有它就无法将人类可读的.java源代码编译成JVM能执行的.class字节码。其核心组件包括：`java`（JVM启动器，负责加载并执行字节码）、`javac`（前端编译器，将.java文件翻译为平台无关的.class文件）、`jar`（归档工具，用于打包类库和资源）、`jps`（JVM进程查看器）等。理解JDK的组成，有助于区分开发阶段（需JDK）与部署阶段（仅需JRE），避免在服务器上错误安装完整开发套件而引入安全风险。

### 1.2 JDK版本演进与选型策略
*   **长期支持版（LTS）与非LTS版的本质区别**：自JDK 11起，Oracle确立了每两年发布一个LTS版本的节奏（如JDK 11、17、21），这些版本获得至少8年的商业支持与安全更新，是企业级应用的绝对首选；而非LTS版本（如JDK 18、19、20）仅提供6个月支持，主要用于尝鲜新特性（如虚拟线程、模式匹配）。对于初学者，强烈推荐选择**JDK 21（2023年9月发布的最新LTS）**，它集成了Project Loom的虚拟线程（极大提升高并发I/O性能）、switch表达式增强、未命名变量与模式等现代化语法，且社区生态（Spring Boot 3.x、Hibernate 6.x）已全面适配。切勿使用已停止维护的JDK 8（2017年结束免费更新）或JDK 1.8（命名过时），因其缺乏现代安全补丁与性能优化。

## 二、详细示例与案例
### 2.1 全平台实操安装流程（Windows/macOS/Linux）
*   **Windows系统安装详解**：首先访问Oracle官网（https://www.oracle.com/java/technologies/downloads/）或OpenJDK社区（如Adoptium、Amazon Corretto），下载JDK 21的x64 MSI安装包。双击运行后，安装向导默认将JDK安装至`C:\Program Files\Java\jdk-21`目录。关键步骤在于**环境变量配置**：右键“此电脑”→“属性”→“高级系统设置”→“环境变量”，在“系统变量”中新建`JAVA_HOME`变量，值设为`C:\Program Files\Java\jdk-21`；再编辑`Path`变量，新增`%JAVA_HOME%\bin`。配置完成后，打开新命令提示符，输入`java -version`应返回`java version "21"...`，`javac -version`应显示相同版本号，证明JDK已成功注册到系统路径。

### 2.2 环境变量深度解析与故障排查
*   **JAVA_HOME与PATH的协同机制**：`JAVA_HOME`是一个指向JDK安装根目录的**逻辑路径别名**，其存在意义在于解耦具体安装路径与工具调用——当JDK升级时，只需修改`JAVA_HOME`值，所有依赖它的工具（Maven、Gradle、IDE）自动生效。而`PATH`则定义了操作系统搜索可执行文件的目录列表，`%JAVA_HOME%\bin`被添加至此，使得`java`、`javac`等命令能在任意目录下被Shell识别。常见故障如`'java' 不是内部或外部命令`，90%源于`PATH`未正确包含`%JAVA_HOME%\bin`，或`JAVA_HOME`路径中存在中文、空格（需用英文引号包裹）；若`java -version`返回旧版本，则说明`PATH`中存在多个JDK路径，需将新JDK的`bin`目录置于`PATH`最前端。

## 三、现状分析
### 3.1 技术生态与安全现状（2024年数据）
*   **主流JDK发行版市场占比与安全态势**：根据2024年JetBrains开发者调查报告，Adoptium（Eclipse Temurin）以42%的份额成为最受欢迎的OpenJDK发行版，其次为Amazon Corretto（23%）和Oracle JDK（18%）。安全层面，CVE-2023-25180（JNDI注入漏洞）影响所有JDK 8u361之前版本，而JDK 21已通过默认禁用远程JNDI查找彻底修复。更值得关注的是，Oracle自2023年起对JDK 17+的LTS版本实行**免费商用许可**（NFTL协议），允许在生产环境无限制使用，这标志着Java生态正式告别“付费才能商用”的历史。因此，企业迁移至JDK 21不仅是技术升级，更是降低合规风险的战略选择。

## 四、常见误区
### 4.1 “安装完JDK就万事大吉”的认知陷阱
*   **错误表现**：安装MSI包后未配置环境变量，直接运行IDE（如IntelliJ IDEA）却提示“Cannot determine path to 'tools.jar'”；或在命令行执行`javac HelloWorld.java`报错“找不到javac命令”。**根本原因**在于MSI安装器仅完成文件复制，未自动注入系统路径，而IDE依赖`JAVA_HOME`定位JDK工具链。**正确做法**是严格按前述步骤手动配置`JAVA_HOME`与`PATH`，并在配置后**重启所有终端与IDE**（因环境变量变更需进程重新加载）。**避免方法**：安装后立即执行`echo %JAVA_HOME%`（Windows）或`echo $JAVA_HOME`（macOS/Linux）验证变量值，并用`where java`（Windows）或`which java`（macOS/Linux）确认可执行文件位置，形成标准化验证闭环。

## 五、实践建议
### 5.1 分步式练习任务
*   **任务步骤**：1) 下载Adoptium JDK 21 for Windows x64；2) 执行安装并记录安装路径；3) 手动配置`JAVA_HOME`与`PATH`；4) 在CMD中依次执行`java -version`、`javac -version`、`java -XshowSettings:properties -version`（查看JVM系统属性）；5) 创建`HelloWorld.java`文件，编写标准主类，用`javac`编译，再用`java`运行。**预期结果**：所有命令返回JDK 21版本信息；`HelloWorld.class`成功生成并输出“Hello, World!”。**验证方法**：检查`java -XshowSettings:properties`输出中的`java.home`是否指向你配置的`JAVA_HOME`路径，且`os.arch`显示`amd64`（证明64位JDK正确加载）。

### 5.2 延伸阅读权威资源
*   **官方文档**：Oracle JDK 21 Documentation（https://docs.oracle.com/en/java/javase/21/）提供最精准的API与工具说明；**经典书籍**：《深入理解Java虚拟机（第3版）》第1章详述JDK/JRE/SDK概念辨析；**实战课程**：B站BV1cV8BeCESA视频（已嵌入）涵盖从下载到IDE集成的全流程演示；**社区指南**：Adoptium官方安装手册（https://adoptium.net/installation/）针对各Linux发行版提供Shell脚本一键配置方案。

## 六、小结与思考
### 6.1 核心要点回顾
*   **JDK本质**：是Java开发的“操作系统”，包含编译、运行、调试全生命周期工具；**版本选择**：必须优先选用LTS版（当前为JDK 21），规避非LTS版的短期支持风险；**环境变量**：`JAVA_HOME`是JDK的“身份证”，`PATH`是它的“通行令牌”，二者缺一不可；**验证铁律**：安装后必须用`java -version`与`javac -version`双重校验，且需在新终端中执行。

### 6.2 思考题
*   如果在同一台机器上需要同时开发基于Spring Boot 2.7（要求JDK 8）和Spring Boot 3.2（要求JDK 21）的两个项目，如何设计环境变量方案以避免版本冲突？请结合IDE（如IntelliJ）的JDK Project SDK配置与Maven Toolchains插件机制，给出可落地的多版本共存策略。
