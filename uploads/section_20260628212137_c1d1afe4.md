# JDK安装与开发环境配置

## 一、核心知识讲解
### 1.1 什么是JDK及其组成结构
*   **JDK（Java Development Kit）**：是Java语言的官方软件开发工具包，专为Java开发者设计，包含编译器（javac）、运行时环境（JRE）、调试器（jdb）、文档生成器（javadoc）、打包工具（jar）等全套开发组件。它不仅是Java程序运行的基础，更是代码编写、编译、调试、部署全流程的核心支撑。JDK内部严格分层：最底层是JVM（Java虚拟机），负责字节码解释执行；中间层是Java类库（如java.lang、java.util），提供标准API；顶层是开发工具集，使开发者无需从零构建编译链路。理解JDK不是“一个安装包”，而是一个完整生态入口，是避免后续出现“找不到javac命令”或“版本冲突”的前提。

### 1.2 JDK版本演进与选型策略
*   **LTS（长期支持版）与非LTS版差异**：自JDK 11起，Oracle采用半年发布周期+三年LTS策略。当前主流LTS版本为JDK 17（2021年9月发布，支持至2029年）和JDK 21（2023年9月发布，支持至2031年）。非LTS版如JDK 22虽含新特性（虚拟线程、模式匹配增强），但仅获6个月支持，不适合生产环境。初学者强烈建议选择JDK 21——它兼容Spring Boot 3.x、支持GraalVM原生镜像、内置ZGC低延迟垃圾回收器，并已通过OpenJDK社区全面验证。错误选型（如误装JDK 8）将导致无法使用现代框架特性（如record类、switch表达式），并埋下未来迁移成本。

## 二、详细示例与案例
### 2.1 Windows/macOS/Linux三平台安装实操流程
*   **Windows平台（以JDK 21为例）**：首先访问https://adoptium.net/（推荐开源Eclipse Temurin构建），选择JDK 21 x64 MSI安装包。双击运行后，在安装向导中务必勾选“Add to PATH”选项——这是避免后续终端报错“'javac' is not recognized”的关键。安装完成后，打开CMD执行`java -version`与`javac -version`双重验证，输出应均为“21.0.3”。若仅`java`有效而`javac`失效，说明PATH未正确包含bin目录，需手动在系统环境变量中添加`C:\Program Files\Eclipse Adoptium\jdk-21.0.3.9-hotspot\bin`。

### 2.2 配置JAVA_HOME与PATH的深度解析
*   **JAVA_HOME环境变量本质**：它并非Java运行必需，而是构建工具（Maven、Gradle）、IDE（IntelliJ IDEA）及企业级框架（Spring Boot）识别JDK根目录的“协议约定”。其值必须指向JDK安装根目录（如`C:\Program Files\Eclipse Adoptium\jdk-21.0.3.9-hotspot`），而非bin子目录。PATH则需追加`%JAVA_HOME%\bin`（Windows）或`$JAVA_HOME/bin`（macOS/Linux），使终端能直接调用javac等命令。常见错误是将JAVA_HOME设为`...\bin`，导致Maven报错“Failed to execute goal org.apache.maven.plugins:maven-compiler-plugin:3.11.0:compile”，因插件无法定位tools.jar（已移除）或rt.jar（模块化后不存在）。

## 三、现状分析
### 3.1 技术生态层面的JDK采用率与兼容性挑战
*   根据2024年JetBrains开发者调查报告，JDK 21已成为全球68%专业开发者的首选版本，远超JDK 17（22%）与JDK 8（仅剩4%）。这一趋势源于JDK 21对云原生架构的深度适配：其虚拟线程（Virtual Threads）使单机QPS提升300%，被Netflix用于重构实时推荐服务；新的Scoped Memory API正加速替代传统堆外内存管理方案。然而，遗留系统仍面临严峻兼容性问题——某银行核心系统升级至JDK 21时，因移除了SecurityManager（JDK 17废弃，JDK 21彻底删除），导致基于Java Security Policy的权限控制模块崩溃，最终通过迁移到Spring Security ACL方案解决。这警示开发者：环境配置不仅是安装步骤，更是技术债务评估的起点。

## 四、常见误区
### 4.1 混淆JDK、JRE与JVM的概念边界
*   **错误表现**：下载安装包时选择“JRE”而非“JDK”，导致无法编译.java文件，IDE报错“Cannot run program 'javac'”。**根本原因**在于JRE（Java Runtime Environment）仅含JVM与类库，专为运行已编译程序设计；而JDK是JRE的超集，额外提供开发工具链。**正确做法**是始终安装JDK——即使仅运行程序，现代构建工具（如Gradle）也依赖JDK中的javac进行增量编译。**避免方法**：牢记口诀“写代码用JDK，跑程序用JRE”，并在下载页认准“Development Kit”字样，避开纯“Runtime Environment”选项。

## 五、实践建议
### 5.1 分步验证练习任务
*   **步骤1**：在任意目录创建HelloWorld.java文件，内容为`public class HelloWorld { public static void main(String[] args) { System.out.println("JDK配置成功！"); } }`；**步骤2**：终端进入该目录，执行`javac HelloWorld.java`生成.class文件；**步骤3**：执行`java HelloWorld`（注意无.class后缀）；**预期结果**：终端输出“JDK配置成功！”；**验证方法**：若步骤2报错“command not found”，检查PATH是否含bin目录；若步骤3报错“Could not find or load main class”，检查是否误输`java HelloWorld.class`或当前目录有同名.class干扰。

### 5.2 延伸阅读资源
*   **官方文档**：Oracle JDK 21 Installation Guide（https://docs.oracle.com/en/java/javase/21/install/overview-jdk-installation.html）提供各平台权威配置说明；**实战教程**：B站BV1cV8BeCESA视频中“多版本共存方案”章节，演示SDKMAN工具管理JDK 8/17/21切换；**深度书籍**：《深入理解Java虚拟机（第3版）》第1章详解JDK目录结构与工具链原理，帮助建立系统级认知。

## 六、小结与思考
### 6.1 核心要点回顾
*   **JDK是开发基石**：必须安装完整JDK而非JRE，且优先选用JDK 21 LTS版本；**环境变量是关键枢纽**：JAVA_HOME指向根目录，PATH追加bin路径，二者缺一不可；**验证需闭环**：javac编译 + java执行双步骤验证，缺一不可；**生态意识不可少**：JDK版本选择直接影响框架兼容性与性能上限。

### 6.2 思考题
*   如果公司项目要求必须使用JDK 8（因依赖老旧加密算法），而你的本地已安装JDK 21，如何在不卸载的前提下，让Maven构建时自动使用JDK 8？请结合MAVEN_OPTS、pom.xml配置及IDE设置三个维度给出可落地方案。
