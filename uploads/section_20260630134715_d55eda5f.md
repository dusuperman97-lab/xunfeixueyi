# JDK安装与开发环境配置

## 一、核心知识讲解
### 1.1 什么是JDK？
*   **JDK（Java Development Kit）**：是Java语言的**软件开发工具包**，它不仅包含运行Java程序所必需的**JRE（Java Runtime Environment）**，还额外提供了编译器（javac）、调试器（jdb）、文档生成工具（javadoc）等开发者专用工具。初学者常混淆JDK与JRE——JRE仅用于**运行**已编译的.class文件，而JDK是**开发、编译、调试、部署**整个Java应用的完整套件。JDK版本演进至关重要：JDK 8长期支持（LTS）仍被广泛使用；JDK 17（2021年发布）和JDK 21（2023年LTS）引入了虚拟线程（Virtual Threads）、模式匹配增强、Record类等现代化特性，大幅提升并发性能与代码简洁性。选择JDK 17或21作为学习起点，既能获得稳定支持，又能接触前沿特性。

### 1.2 JDK安装全流程（Windows/macOS/Linux三平台）
*   **下载与校验**：务必从Oracle官网（https://www.oracle.com/java/technologies/downloads/）或OpenJDK权威发行版（如Eclipse Temurin、Amazon Corretto）下载。以Temurin JDK 21为例，Windows选x64 MSI安装包，macOS选ARM64 PKG（M1/M2芯片）或x64 PKG（Intel），Linux选tar.gz压缩包。下载后核对SHA256校验码，防止镜像篡改。MSI安装包双击即可图形化安装；Linux需解压至`/opt/jdk-21`并设置权限：`sudo chown -R root:root /opt/jdk-21 && sudo chmod -R 755 /opt/jdk-21`。

## 二、详细示例与案例
### 2.1 应用场景
*   **企业级Java开发环境统一化**：某金融科技公司为保障微服务集群稳定性，强制要求所有开发机安装JDK 21 + Maven 3.9 + IntelliJ IDEA 2023.3，并通过Ansible脚本自动化部署JDK及环境变量。该策略使新员工入职配置时间从平均4小时缩短至15分钟，且规避了因JDK版本不一致导致的`UnsupportedClassVersionError`等编译异常。在CI/CD流水线中，JDK版本被写入Dockerfile的`FROM eclipse-temurin:21-jre-jammy`基础镜像，确保测试与生产环境完全一致，这是DevOps实践的核心前提。

### 2.2 代码示例
*   **验证JDK安装与环境变量配置**：创建`HelloJDK.java`文件，内容如下：
```java
// HelloJDK.java —— 验证JDK编译与运行能力
public class HelloJDK {
    public static void main(String[] args) {
        // 1. 输出JDK版本信息（关键诊断步骤）
        System.out.println("Java运行时版本：" + System.getProperty("java.version"));
        System.out.println("Java安装路径：" + System.getProperty("java.home"));
        System.out.println("JDK主目录：" + System.getProperty("java.vendor"));
        
        // 2. 演示JDK 21新特性：字符串模板（预览特性需启用）
        String name = "Java Developer";
        // 注意：JDK 21中字符串模板为预览特性，编译需加--enable-preview参数
        // System.out.println("欢迎 %s！".formatted(name)); // 替代String.format()
        
        // 3. 虚拟线程基础验证（JDK 21 LTS核心特性）
        try {
            // 创建10万个虚拟线程（传统线程会OOM，虚拟线程轻量）
            for (int i = 0; i < 100000; i++) {
                Thread.ofVirtual().unstarted(() -> {
                    System.out.println("虚拟线程 " + Thread.currentThread().getName() + " 执行中");
                }).start();
            }
            System.out.println("10万虚拟线程已启动！");
        } catch (Exception e) {
            System.err.println("虚拟线程测试失败：" + e.getMessage());
            // 若报错，说明未启用预览特性，需重新编译运行
        }
        
        // 4. 环境变量PATH验证：调用系统命令
        try {
            Process p = Runtime.getRuntime().exec("javac -version");
            java.io.BufferedReader reader = new java.io.BufferedReader(
                new java.io.InputStreamReader(p.getInputStream()));
            String line;
            while ((line = reader.readLine()) != null) {
                System.out.println("javac版本：" + line);
            }
        } catch (Exception e) {
            System.err.println("javac命令不可用，请检查PATH配置！");
        }
    }
}
```
编译与运行命令（Windows PowerShell / macOS/Linux Terminal）：
```bash
# 编译（生成HelloJDK.class）
javac HelloJDK.java
# 运行（输出版本与诊断信息）
java HelloJDK
# 若需测试虚拟线程，启用预览特性：
java --enable-preview HelloJDK
```

## 三、现状分析
### 3.1 技术/应用层面
*   根据2024年JetBrains开发者生态调查报告，JDK 17与JDK 21合计占据生产环境JDK使用率的78.3%，其中JDK 21在新项目中采用率达62.1%，成为事实上的新标准。OpenJDK生态已全面成熟：Eclipse Temurin市场占有率达41%，Amazon Corretto达29%，微软Build of OpenJDK占12%。值得注意的是，JDK 21的虚拟线程（Project Loom）将高并发服务的线程内存开销从传统线程的~1MB/个降至~1KB/个，使单机处理100万并发连接成为可能。国内主流云厂商（阿里云、腾讯云）已在其容器服务中默认集成JDK 21镜像，并提供自动JVM调优建议，标志着Java开发环境正从“手动配置”迈向“智能托管”。

## 四、常见误区
### 4.1 易错点
*   **错误表现**：命令行输入`java -version`显示版本，但`javac -version`提示“'javac' 不是内部或外部命令”。**原因**：仅将JRE路径（如`C:\Program Files\Java\jre1.8.0_301\bin`）加入PATH，而未添加JDK的`bin`目录（如`C:\Program Files\Java\jdk-21.0.1\bin`）。JRE不含编译器`javac`，仅含运行时`java`。**正确做法**：必须将JDK安装目录下的`bin`子目录（如`C:\Program Files\Java\jdk-21.0.1\bin`）添加到系统PATH环境变量，而非JRE路径。**避免方法**：安装MSI包时勾选“Add to PATH”选项；手动配置后，在新终端窗口执行`echo %PATH%`（Windows）或`echo $PATH`（macOS/Linux）确认路径存在，并用`where javac`（Windows）或`which javac`（macOS/Linux）验证可执行文件位置。

## 五、实践建议
### 5.1 练习任务
*   **步骤**：1）访问https://adoptium.net/ 下载Eclipse Temurin JDK 21；2）完成安装并配置PATH；3）创建`JdkDiagnose.java`，复制2.2节代码；4）在命令行依次执行`javac JdkDiagnose.java`与`java JdkDiagnose`；5）记录输出结果。**预期结果**：成功打印Java版本、安装路径、`javac`版本，且无“命令未找到”错误。**验证方法**：若`javac`失败，检查PATH是否指向JDK `bin`目录；若虚拟线程报错，尝试添加`--enable-preview`参数；最终应看到“10万虚拟线程已启动！”日志（实际可能因控制台缓冲截断，但无异常即成功）。

## 六、小结与思考
### 6.1 核心要点回顾
*   **JDK是开发基石**：它不仅是运行环境，更是编译、调试、性能分析的全栈工具集，选择LTS版本（JDK 17/21）是企业级开发的黄金标准。**PATH配置是成败关键**：必须精准指向JDK的`bin`目录，任何偏差都将导致编译中断。**跨平台一致性**：Windows的MSI、macOS的PKG、Linux的tar.gz虽安装方式不同，但环境变量配置逻辑完全一致，掌握其共性可快速迁移。**新特性驱动学习**：JDK 21的虚拟线程并非噱头，它从根本上重构了高并发编程范式，初学者应尽早建立“轻量级线程”心智模型。

### 6.2 思考题
*   如果公司遗留系统强制要求JDK 8，而新模块需用JDK 21的虚拟线程，如何在同一台开发机上安全共存两个JDK版本？请设计一套基于IDEA项目级SDK配置+Maven `maven-compiler-plugin`版本绑定的解决方案，并说明其如何避免`mvn compile`时的版本冲突。
