# 迭代器与生成器

## 一、核心知识讲解
### 1.1 迭代器：Python数据遍历的协议基石
*   **迭代器（Iterator）**：是实现了迭代器协议（Iterator Protocol）的对象，必须同时具备`__iter__()`和`__next__()`两个特殊方法。`__iter__()`返回迭代器自身（通常为`self`），`__next__()`则负责返回序列中的下一个元素；当没有更多元素时，它必须抛出`StopIteration`异常。迭代器的本质是一种“状态机”，它封装了遍历过程中的当前位置和内部状态，使得外部代码无需关心底层数据结构如何存储或索引，只需通过统一的`next()`接口获取数据。这种设计极大提升了代码的抽象层次和可组合性，是Python中`for`循环、列表推导式等语法糖的底层支撑机制。例如，一个自定义的`RangeIterator`类可以按需生成整数序列，每次调用`next()`只计算并返回下一个数字，完全不依赖于预先构建的列表，从而节省了大量内存空间。

### 1.2 生成器：用函数语法实现的迭代器
*   **生成器（Generator）**：是一种特殊的迭代器，它并非通过显式定义类和方法来实现，而是由包含`yield`语句的函数（生成器函数）或生成器表达式（如`(x*2 for x in range(10))`）所创建。当调用一个生成器函数时，它并不会立即执行函数体内的代码，而是返回一个生成器对象——这个对象就是一个迭代器。每次调用其`__next__()`方法时，函数体从上次`yield`暂停的位置继续执行，直到遇到下一个`yield`或函数结束。`yield`不仅返回一个值，还自动保存了函数的全部局部变量、指令指针和执行上下文，这种“协程式”的暂停与恢复能力，使得生成器成为实现复杂状态机、数据流水线和异步I/O的绝佳工具。与普通迭代器相比，生成器语法更简洁、逻辑更清晰，且天然支持惰性求值（Lazy Evaluation），是Python中函数式编程思想的集中体现。

## 二、详细示例与案例
### 2.1 应用场景：处理10GB日志文件的内存优化实践
在实际运维场景中，我们常需分析海量Web服务器日志（如Nginx access.log），其体积可达10GB以上。若使用传统方式`lines = open('access.log').readlines()`，会将全部文本一次性加载进内存，极易导致内存溢出（OOM）。而采用生成器方案，则能以恒定内存（约几KB）完成全量分析。具体流程是：首先定义一个`log_line_generator()`生成器函数，它逐行打开并读取文件；然后将其与多个过滤、解析、聚合的生成器函数（如`filter_404_errors()`、`parse_user_agent()`）通过管道式组合（`for event in parse_user_agent(filter_404_errors(log_line_generator()))`），形成一条高效的数据处理流水线。整个过程中，每一行日志仅被创建、处理、丢弃一次，内存占用与文件大小无关，只与单行长度相关。这种模式已被广泛应用于ELK栈、Prometheus监控告警系统等工业级项目中，是大数据预处理的标准范式。

### 2.2 代码示例：斐波那契数列生成器与自定义迭代器对比实现
```python
# 【方案一】生成器函数：语法简洁，状态自动管理
def fibonacci_generator(n):
    """生成前n个斐波那契数"""
    a, b = 0, 1
    count = 0
    while count < n:
        yield a
        a, b = b, a + b
        count += 1

# 【方案二】手动实现迭代器类：显式管理状态，更底层可控
class FibonacciIterator:
    def __init__(self, n):
        self.n = n
        self.a, self.b = 0, 1
        self.count = 0

    def __iter__(self):
        return self

    def __next__(self):
        if self.count >= self.n:
            raise StopIteration
        current = self.a
        self.a, self.b = self.b, self.a + self.b
        self.count += 1
        return current

# 【方案三】生成器表达式：一行代码，极致简洁
fib_gen_expr = (lambda a,b,n: (a for _ in range(n) if not [a.__setitem__(0, b) or b.__setitem__(0, a[0]+b[0]) for a,b in [(a,b)]][0]))([0],[1],10)
# 实际推荐写法（更清晰）：
fib_expr = (lambda a,b: (a for _ in range(10) if not [a:=b or b:=a+b][0]))(0,1)

# 使用示例与性能对比
if __name__ == "__main__":
    import time
    
    # 测试生成器函数
    start = time.time()
    fib_list1 = list(fibonacci_generator(100000))
    time1 = time.time() - start
    
    # 测试迭代器类
    start = time.time()
    fib_list2 = list(FibonacciIterator(100000))
    time2 = time.time() - start
    
    print(f"生成器函数耗时: {time1:.4f}s")
    print(f"迭代器类耗时: {time2:.4f}s")
    print(f"结果一致性: {fib_list1 == fib_list2}")
    
    # 验证内存友好性：生成器对象本身极小
    gen_obj = fibonacci_generator(1000000)
    print(f"生成器对象大小: {gen_obj.__sizeof__()} 字节")
    print(f"完整列表大小: {fib_list1.__sizeof__()} 字节")
```

## 四、常见误区
### 4.1 易错点：误将生成器对象直接赋值给变量并期望重复遍历
错误表现是：`gen = fibonacci_generator(5); list(gen); list(gen)` 第二次`list()`返回空列表`[]`。原因在于生成器是一次性消耗品（Exhaustible），其内部状态在首次遍历完成后即停留在`StopIteration`，后续调用`next()`会立即抛出异常。正确做法是：若需多次遍历，应重新调用生成器函数创建新对象（`list(fibonacci_generator(5))`），或先将其转换为不可变序列（如`tuple(gen)`）。避免方法是在代码审查中严格禁止对同一生成器对象进行多次`for`循环或`list()`转换；团队可制定规范，要求所有公共API返回生成器时，在文档中明确标注“此生成器为一次性对象”。
