# 迭代器与生成器

## 一、核心知识讲解
### 1.1 迭代器协议与底层机制
*   **迭代器（Iterator）**：是Python中实现**迭代器协议**的对象，必须同时实现`__iter__()`和`__next__()`两个特殊方法。`__iter__()`返回迭代器自身（通常`return self`），`__next__()`则负责返回序列中的下一个元素；当没有更多元素时抛出`StopIteration`异常。这种设计使得迭代过程完全可控——例如自定义一个倒序遍历列表的迭代器，只需在`__next__()`中维护索引并递减，就能实现与内置`reversed()`相同的效果，而无需创建新列表。迭代器的本质是**状态机**，它封装了遍历逻辑和当前位置，因此一次遍历后即耗尽，无法重复使用，这既是内存友好的体现，也是其“单向不可逆”特性的根源。

### 1.2 生成器函数与惰性求值
*   **生成器（Generator）**：是一种特殊的迭代器，由包含`yield`语句的函数创建。当调用生成器函数时，并不立即执行函数体，而是返回一个生成器对象；每次调用`next()`或进入`for`循环时，函数从上次`yield`暂停处继续执行，直到遇到下一个`yield`或函数结束。这种**惰性求值（Lazy Evaluation）**机制意味着数据仅在需要时才被计算和生成，极大节省内存——例如处理10GB日志文件时，生成器可逐行读取并处理，全程内存占用仅约几KB，而一次性`readlines()`则可能触发内存溢出。生成器函数本质上是语法糖，CPython会将其编译为状态机字节码，`yield`语句对应状态切换点，使开发者无需手动管理状态变量即可构建复杂的数据流管道。

### 1.3 生成器表达式与性能权衡
*   **生成器表达式**：形如`(x**2 for x in range(1000000))`，是创建生成器的简洁语法，相比列表推导式`[x**2 for x in range(1000000)]`，它不预先构建完整列表，而是按需生成每个平方数。然而需注意：生成器表达式虽省内存，但若需多次遍历（如先求最大值再求平均值），必须重新创建生成器，因其一次性耗尽特性；此时应权衡是否改用`itertools.tee()`复制迭代器，或转为列表（当数据量可控时）。此外，生成器表达式嵌套过深（如三层嵌套）可能导致调试困难，建议辅以`itertools.chain()`等工具库进行扁平化处理，提升代码可读性与可维护性。

## 二、详细示例与案例
### 2.1 应用场景：大数据流式处理与无限序列生成
在实时风控系统中，交易流水数据以每秒万级速度持续写入Kafka，传统方式需将全量数据拉取到内存再分析，极易OOM。采用生成器构建数据管道：首先定义`kafka_stream_generator()`生成器，通过`confluent-kafka`客户端消费消息并`yield`解析后的JSON对象；接着用`filter`生成器筛选高风险交易（如金额>50万），再用`map`生成器计算风险评分；最终通过`itertools.islice()`截取前1000条供模型训练。整个流程内存恒定在~2MB，而同等功能的列表方案需GB级内存。更进一步，生成器可构造数学上的**无限序列**，如斐波那契数列生成器`fibonacci_gen()`，其`while True: yield a; a, b = b, a+b`逻辑永不终止，却可通过`itertools.islice(fibonacci_gen(), 10)`安全获取前10项，完美解决“理论上无限、实践中有限”的工程矛盾。

### 2.2 代码示例：自定义文件迭代器与协程式生成器
```python
# 【案例1】自定义大文件迭代器：支持断点续传与编码自动检测
import chardet
from pathlib import Path

class SmartFileIterator:
    """智能文件迭代器，自动检测编码并支持按块读取"""
    def __init__(self, file_path: str, chunk_size: int = 8192):
        self.file_path = Path(file_path)
        self.chunk_size = chunk_size
        self._file = None
        self._encoding = None
    
    def __enter__(self):
        # 自动检测文件编码
        with open(self.file_path, 'rb') as f:
            raw_data = f.read(10000)  # 读取前10KB样本
            self._encoding = chardet.detect(raw_data)['encoding'] or 'utf-8'
        self._file = open(self.file_path, 'r', encoding=self._encoding)
        return self
    
    def __exit__(self, exc_type, exc_val, exc_tb):
        if self._file:
            self._file.close()
    
    def __iter__(self):
        return self
    
    def __next__(self):
        if not self._file:
            raise StopIteration
        line = self._file.readline()
        if not line:
            raise StopIteration
        return line.strip()

# 使用示例：安全读取GBK编码的超大日志文件
with SmartFileIterator('access.log') as log_iter:
    for i, line in enumerate(log_iter):
        if i >= 100:  # 仅处理前100行
            break
        print(f"Line {i+1}: {line[:50]}...")

# 【案例2】协程式生成器：支持外部数据注入的动态过滤器
def dynamic_filter(threshold_func):
    """协程生成器：根据外部输入动态调整过滤阈值"""
    threshold = yield "Ready"  # 初始化通信
    while True:
        data = yield "Waiting for data"
        if data is not None and threshold_func(data, threshold):
            yield f"ACCEPTED: {data}"
        else:
            yield f"REJECTED: {data}"

# 启动协程并交互
filter_coro = dynamic_filter(lambda x, t: x > t)
print(next(filter_coro))  # "Ready"
print(filter_coro.send(10))  # "Waiting for data"
print(filter_coro.send(5))   # "REJECTED: 5"
print(filter_coro.send(15))  # "ACCEPTED: 15"
```

## 四、常见误区
### 4.1 易错点：混淆可迭代对象与迭代器，导致意外耗尽
错误表现：将同一个生成器对象多次用于不同循环（如先`list(gen)`再`sum(gen)`），第二次调用返回空结果。原因在于生成器是一次性对象，`list()`调用已触发其全部`yield`直至`StopIteration`，后续`sum()`面对空迭代器自然得0。正确做法是：对需多次使用的生成器，要么重新调用生成器函数（`gen = my_gen()`），要么用`itertools.tee(gen, n)`创建n个独立副本。避免方法：养成“生成器即消耗品”的思维习惯，在函数签名中明确标注参数类型（如`def process_data(data_iter: Iterator[int]) -> None`），并配合mypy静态检查拦截误用。

## 六、小结与思考
### 6.1 核心要点回顾
迭代器是遵循协议的状态机，生成器是`yield`驱动的语法糖，二者共同构成Python惰性计算的基石。关键差异在于：迭代器需手动管理状态，生成器由解释器自动维护；所有生成器都是迭代器，但反之不成立。掌握`send()`、`throw()`、`close()`等协程方法，可将生成器升级为双向通信管道，这是构建异步数据流的前置技能。
