# 装饰器与上下文管理器

## 一、核心知识讲解
### 1.1 装饰器：函数行为的动态增强机制
*   **装饰器（Decorator）**：是Python中一种**高阶函数设计模式**，本质是一个接收函数作为参数并返回新函数（或可调用对象）的闭包。其核心价值在于**不修改原函数源码的前提下，为其动态添加横切关注点（Cross-Cutting Concerns）**，如日志记录、性能监控、权限校验、缓存控制等。装饰器通过`@decorator_name`语法糖实现声明式编程，极大提升代码复用性与可维护性。例如，一个`@log_execution`装饰器可在函数调用前后自动打印入口/出口日志，而无需在每个函数内部重复编写`print()`语句；其底层依赖Python的函数是一等公民（First-Class Object）特性，支持将函数作为参数传递、作为返回值返回，并能通过`functools.wraps`保留被装饰函数的元信息（如`__name__`、`__doc__`），避免调试时出现`wrapper`混淆问题。

### 1.2 上下文管理器：资源生命周期的精准控制协议
*   **上下文管理器（Context Manager）**：是Python定义的一套**资源管理协议**，通过实现`__enter__()`和`__exit__()`两个特殊方法的对象来确保代码块执行前后的资源初始化与清理操作。其典型应用场景是文件操作、数据库连接、线程锁等需要显式获取与释放的资源。`with`语句是调用上下文管理器的语法糖，它保证无论`with`块内是否发生异常，`__exit__()`方法都会被执行，从而彻底规避资源泄漏风险。例如，`with open('file.txt') as f:`在进入时调用`__enter__()`返回文件对象，在退出时自动调用`__exit__()`关闭文件句柄；更高级的应用包括使用`contextlib.contextmanager`装饰器将生成器函数转换为上下文管理器，或继承`contextlib.ContextDecorator`类创建**既能用于`with`语句又能作为函数装饰器**的双重用途对象，实现日志跟踪、性能计时等功能的统一抽象。

## 二、详细示例与案例
### 2.1 应用场景：微服务日志与数据库事务协同管理
在构建高可用微服务系统时，需同时保障**请求链路日志的完整性**与**数据库事务的原子性**。传统做法是在每个API处理函数中手动编写日志开始/结束代码及`try...except...finally`事务控制块，导致大量重复逻辑且易出错。采用装饰器+上下文管理器组合方案可优雅解耦：首先定义`@request_logger`装饰器，自动记录HTTP请求ID、路径、耗时及响应状态；其次创建`DatabaseTransaction`上下文管理器，在`__enter__()`中开启数据库会话，在`__exit__()`中根据异常类型决定提交或回滚事务。当二者嵌套使用（如`@request_logger`修饰的函数内使用`with DatabaseTransaction() as tx:`），即可形成分层防护：外层装饰器监控整个请求生命周期，内层上下文管理器精确控制数据持久化边界。这种模式显著提升系统可观测性与数据一致性，已被FastAPI、Django等主流框架深度集成。

### 2.2 代码示例：带异常抑制与性能分析的双重功能装饰器
```python
import time
import functools
from contextlib import ContextDecorator
from typing import Any, Callable, Optional

# 基础性能计时装饰器
def timer(func: Callable) -> Callable:
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            result = func(*args, **kwargs)
            end = time.perf_counter()
            print(f"[TIMER] {func.__name__} 执行耗时: {end - start:.4f}s")
            return result
        except Exception as e:
            end = time.perf_counter()
            print(f"[TIMER] {func.__name__} 执行失败，耗时: {end - start:.4f}s")
            raise
    return wrapper

# 可配置的日志装饰器
def log_calls(level: str = "INFO") -> Callable:
    def decorator(func: Callable) -> Callable:
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            print(f"[{level}] 进入 {func.__name__}，参数: {args}, {kwargs}")
            try:
                result = func(*args, **kwargs)
                print(f"[{level}] 退出 {func.__name__}，返回: {result}")
                return result
            except Exception as e:
                print(f"[{level}] {func.__name__} 抛出异常: {type(e).__name__}: {e}")
                raise
        return wrapper
    return decorator

# 继承ContextDecorator实现双重能力的上下文管理器
class PerformanceTracker(ContextDecorator):
    def __init__(self, name: str = "block"):
        self.name = name
        self.start_time = None
        self.end_time = None

    def __enter__(self):
        self.start_time = time.perf_counter()
        print(f"[PERF] 开始执行 {self.name}")
        return self

    def __exit__(self, exc_type, exc_value, traceback):
        self.end_time = time.perf_counter()
        duration = self.end_time - self.start_time
        if exc_type is None:
            print(f"[PERF] {self.name} 执行成功，耗时: {duration:.4f}s")
        else:
            print(f"[PERF] {self.name} 执行失败，耗时: {duration:.4f}s，异常: {exc_type.__name__}")
        return False  # 不抑制异常

# 综合应用示例
def risky_calculation(n: int) -> int:
    """模拟可能抛出异常的计算函数"""
    if n < 0:
        raise ValueError("输入不能为负数")
    return sum(i * i for i in range(n))

# 使用装饰器组合
@timer
@log_calls("DEBUG")
def process_data(data: list) -> dict:
    """处理数据的主函数"""
    with PerformanceTracker("data_processing"):
        result = 0
        for item in data:
            with PerformanceTracker(f"item_{item}"):
                result += risky_calculation(item)
        return {"sum_of_squares": result, "count": len(data)}

# 测试调用
if __name__ == "__main__":
    try:
        output = process_data([5, 10, -1])  # 最后一个参数会触发异常
        print("最终结果:", output)
    except ValueError as e:
        print("捕获到预期异常:", e)
```

## 四、常见误区
### 4.1 易错点：装饰器未使用`functools.wraps`导致元信息丢失
错误表现是被装饰函数的`__name__`变为`'wrapper'`、`__doc__`为空，导致文档生成工具（如Sphinx）无法提取正确签名，单元测试中`mock.patch`失效，甚至FastAPI的OpenAPI文档无法显示参数说明。根本原因是装饰器内部的闭包函数覆盖了原函数的元信息。正确做法是在装饰器内部使用`@functools.wraps(func)`修饰包装函数，该装饰器会自动复制`func`的`__name__`、`__doc__`、`__module__`等属性到`wrapper`上。避免方法包括：始终将`functools.wraps`作为装饰器开发的强制规范；使用`inspect.signature(wrapper)`验证元信息完整性；在团队代码审查清单中加入此项检查。此外，对于类装饰器，需在`__call__`方法中同样应用`functools.wraps`以确保实例可调用对象的元信息正确。

## 六、小结与思考
### 6.1 核心要点回顾
装饰器是**函数行为的横向增强工具**，适用于日志、监控、认证等跨切面需求，强调对函数调用过程的干预；上下文管理器是**资源生命周期的纵向管控协议**，适用于文件、连接、锁等需成对操作的资源，强调对代码块执行边界的保障。二者可通过`ContextDecorator`基类实现能力融合，体现Python“组合优于继承”的设计哲学。掌握其底层原理（闭包、特殊方法协议、语法糖展开）是写出健壮生产代码的前提。
